# 雾岛共建攻略

由玩家共同维护的雾岛攻略库。这里追求简洁、明确、可复现的信息，不收录未经验证的推论。

## 目录

```text
世界/
├── index.md
├── 地点/
│   └── 地点名/
│       ├── index.md
│       └── 其他主题.md
└── 其他世界相关主题可直接建立 Markdown 文件

职业/
├── index.md
└── 职业名/
    ├── index.md
    └── 其他主题.md
```

- 世界索引：`世界/index.md`
- 地点总览：`世界/地点/地点名/index.md`
- 地点专题：`世界/地点/地点名/主题名.md`
- 其他世界信息：`世界/主题名.md`
- 职业索引：`职业/index.md`
- 职业总览：`职业/职业名/index.md`
- 职业专题：`职业/职业名/主题名.md`

地点和职业目录请使用游戏内正式名称。同一个地点或职业只维护一个目录，不要重复创建近似条目；综合信息写入 `index.md`，独立主题可以在相同目录中新增 Markdown 文件。

## 编写要求

1. **语言精简**：直接写结论和操作方式，删除背景铺垫、重复描述和无关感想。
2. **结构明确**：使用清晰的标题划分主题，让读者能快速定位信息。
3. **多用表格**：属性、条件、步骤、结果等适合对比的信息应优先使用表格。
4. **不要长篇大论**：能用表格或短列表说明的内容，不写成长段文字。
5. **只写亲自验证的行为**：每一条内容都必须来自投稿者在游戏中的实际操作与确认。
6. **禁止推论或猜测**：不写“可能”“大概”“应该”等未经验证的信息，也不根据现象推导机制。
7. **发现错误立即修正**：现有攻略有误时，请直接通过 PR 修改原文，用正确内容及时覆盖错误信息，不要仅在文末追加纠错说明。

## 推荐格式

```markdown
# 名称

## 概览

| 项目 | 内容 |
| --- | --- |
| 类型 | 已验证的信息 |
| 条件 | 已验证的信息 |

## 操作与结果

| 操作 | 条件 | 结果 |
| --- | --- | --- |
| 实际执行的操作 | 触发条件 | 亲自确认的结果 |

## 注意事项

- 只列出亲自验证过的注意事项。
```

## 投稿流程

1. 找到对应文件；如果条目不存在，按照目录规则新建 Markdown 文件。
2. 直接修改或补充已验证的信息。
3. 发起 PR，并确认 PR 模板中的声明。
4. 符合目录限制的投稿会自动合并；发生文件冲突时，需要先解决冲突。

自动合并只检查文件位置，不代表内容一定正确。每位贡献者都可以通过新的 PR 及时覆盖错误内容，让仓库始终保留当前已验证的信息。
